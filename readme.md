# GlobalGrad Tracker — Backend

The REST API, job broker, and monitoring stack behind **GlobalGrad Tracker**. GlobalGrad Tracker is a central, cloud-based workspace that helps students handle every stage of studying abroad: finding universities, contacting professors, preparing documents, checking eligibility, and tracking applications through to an accepted offer.

> Frontend: see [`../global-grad-frontend`](../global-grad-frontend/README.md)

---

## Overview

Preparing to study abroad is usually disorganised. Deadlines are tracked by hand, SOPs and LORs pile up in several versions, eligibility is checked manually, and the details are spread across browser tabs, spreadsheets, and email threads. Tools like Google Drive, Excel, and Gmail each cover one piece, and none of them tracks the whole workflow.

This backend gives the platform one structured source of truth:

- **University database**: universities, programs, scholarships, and professors, stored in PostgreSQL.
- **Web scrapers**: keep the database filled with real program and scholarship data.
- **Recommendation / eligibility engine**: matches a student's GPA and IELTS score against program requirements.
- **Role-based auth**: student, teacher, and admin accounts using self-implemented OAuth2 password flow + JWT.
- **Async job broker**: runs long tasks (scraping, emails) outside the request cycle.
- **Observability**: Prometheus metrics with a ready-made Grafana dashboard.

## Features

| Area | What it does | Endpoints |
|---|---|---|
| **Authentication** | OAuth2 password flow that returns a JWT (valid for 7 days). Passwords are hashed with `pbkdf2_sha256`. | `POST /auth/token` |
| **Users & roles** | Student self-registration, admin-managed users, current-user profile. Roles: `student`, `teacher`, `admin`. | `POST /users/students`, `POST /users/`, `GET /users/me`, `GET /users/` *(admin)*, `GET/DELETE /users/{id}` |
| **University database** | Universities with ranking, country, city, and website. | `GET/POST /universities/`, `GET /universities/{id}` |
| **Programs** | Programs with tuition, duration, deadline, requirements, minimum GPA, and minimum IELTS. | `GET/POST /programs/`, `GET /programs/{id}` |
| **Scholarships** | Funding opportunities linked to universities: coverage, eligibility, deadline, and link. | `GET /scholarships/`, `GET /scholarships/{id}` |
| **Professor tracker** | Professors with research area and department, linked to universities and programs. | `GET/POST /professors/`, `GET /professors/{id}`, `POST /professors/{id}/programs` |
| **Outreach log** | Records emails sent by students to professors about a program. | `GET/POST /emails/` |
| **Eligibility & recommendations** | Scores every program against a student's GPA and IELTS (requirements met, plus a bonus for lower tuition) and returns the top N matches. | `POST /recommendations/` |
| **Data scraping** | Admin-triggered scraping of **University of Melbourne**, **Oxford**, and **NUS**. The scrape runs as a background job. | `POST /scrape/universities` *(admin)* |
| **Background jobs** | Submit jobs and check their status (`pending` → `running` → `finished` / `error`). | `GET/POST /jobs/`, `GET /jobs/{id}` |
| **Data feedback** | Users can flag a wrong field on any entity and suggest a correction. | `POST /feedback/` |
| **Health & metrics** | Liveness check and Prometheus metrics. | `GET /`, `GET /metrics` |

Interactive API docs are generated by FastAPI at **`/docs`** (Swagger UI) and **`/redoc`**.

## Architecture

```
            ┌──────────────────────┐
            │  Next.js Frontend    │
            └──────────┬───────────┘
                       │ HTTPS (local dev exposed via ngrok)
                       ▼
┌───────────────────────────────────────────┐        ┌────────────────────────┐
│  api  (FastAPI + Uvicorn)        :8000    │  WS    │  broker  (websockets)  │
│  routes → schemas → models (SQLAlchemy)   │───────▶│  :8765  job intake     │
│  JWT auth · CORS · /metrics               │ submit │  :8001  /metrics       │
└──────────────────┬────────────────────────┘  _job  │  worker loop → scrapers│
                   │                                 └───────────┬────────────┘
                   │ SQLAlchemy                                  │
                   ▼                                             ▼
          ┌──────────────────────────────────────────────────────────┐
          │                PostgreSQL 17   :5432                     │
          │ users · universities · programs · scholarships ·         │
          │ professors · emails · jobs · feedback                    │
          └──────────────────────────────────────────────────────────┘

   Prometheus :9090  ── scrapes ──▶ api:8000/metrics, broker:8001
   Grafana    :3001  ── reads  ──▶ Prometheus (dashboard pre-provisioned)
```

**How a scrape job runs**

1. An admin calls `POST /scrape/universities` with `{"sources": ["oxford", "nus"]}`.
2. The API sends a `submit_job` message to the broker over WebSocket. The broker saves a `Job` row with status `pending`.
3. The broker's worker loop picks up pending jobs, marks each one `running`, and calls the matching scraper (`app/scrapers/universities/*`).
4. Scraped universities, programs, and scholarships are saved to PostgreSQL. The job is then marked `finished` or `error`.
5. The admin dashboard checks progress with `GET /jobs/`.

**Scaling:** every service runs in its own Docker container. The stateless API and the broker/worker can be scaled separately. Jobs are stored in the database, so work isn't lost if a worker restarts.

## Tech Stack

- **Language / framework:** Python 3.11, FastAPI, Uvicorn
- **Database:** PostgreSQL 17, SQLAlchemy ORM
- **Auth:** OAuth2 password flow (self-implemented), JWT (`python-jose`), `passlib`
- **Async jobs:** custom WebSocket broker (`websockets`) with a DB-backed queue
- **Scraping:** `requests` + BeautifulSoup4
- **Monitoring:** Prometheus + Grafana
- **Containerisation / deployment:** Docker Compose; ngrok for exposing the local API

## How to Run

### Option 1: Docker (recommended)

You need Docker and Docker Compose.

```bash
cd backend
docker compose up --build
```

| Service | URL |
|---|---|
| API | http://localhost:8000 |
| API docs (Swagger) | http://localhost:8000/docs |
| Job broker (WebSocket) | ws://localhost:8765 |
| Prometheus | http://localhost:9090 |
| Grafana | http://localhost:3001 (user `admin`, password `admin`) |
| PostgreSQL | `localhost:5432`, db `admission_platform`, user `postgres`, password `admin` |

Tables are created automatically when the API starts. The source folder is mounted into the containers, so code changes show up after a container restart.

### Option 2: Manual (local Python)

You need Python 3.11+ and a running PostgreSQL instance.

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

> `DATABASE_URL` in [`app/core/database.py`](backend/app/core/database.py) points at host `postgres` (the Docker service name). If you run outside Docker, change it to `localhost`. You can start only the database with `docker compose up postgres`.

Start the API and the broker in two separate terminals:

```bash
# terminal 1: API
uvicorn app.main:app --reload

# terminal 2: job broker + worker (needed for scraping/jobs)
python -m app.broker.broker
```

### Exposing the API to the frontend (ngrok)

```bash
ngrok http 8000
```

Put the generated URL in the frontend's API base URL (see the frontend README).

### Quick check

```bash
# register a student
curl -X POST http://localhost:8000/users/students \
  -H "Content-Type: application/json" \
  -d '{"name":"Demo","email":"demo@example.com","password":"secret"}'

# log in
curl -X POST http://localhost:8000/auth/token -d "username=demo@example.com&password=secret"

# get program recommendations
curl -X POST http://localhost:8000/recommendations/ \
  -H "Content-Type: application/json" -d '{"gpa":3.6,"ielts":7.0,"top_n":5}'
```

To run the full job flow (user → token → REST job + WebSocket job → poll status) in one go:

```bash
python tools/demo_client.py
```

### Creating an admin

Scraping, listing users, and the admin dashboard need an `admin` account. Create one with `POST /users/` and `"role": "admin"`.
